# SpookyNeuro — Creature Lab

Исходный код общий, установка и пакеты разделены по ОС:

| | Windows x86_64 | Linux x86_64 (Arch) |
| --- | --- | --- |
| Инструкция | [INSTALL_WINDOWS_RU.txt](INSTALL_WINDOWS_RU.txt) | [INSTALL_ARCH_RU.txt](INSTALL_ARCH_RU.txt) |
| Установка | Автоматически при первом запуске | `bash scripts/setup_3d.sh` |
| Запуск | `Start SpookyNeuro.cmd` | `bash scripts/run_3d.sh` |
| Без генерации | `Offline Preview.cmd` | `bash scripts/run_3d.sh --offline` |
| Сборка/упаковка из исходников | `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build_windows.ps1` | `python scripts/package_arch.py` |
| Архив | `dist/windows/SpookyNeuro-Windows-x86_64.zip` | `dist/linux/SpookyNeuro-Arch-x86_64.zip` |

Windows-пакет содержит экспортированные EXE/PCK и установщик нейросетевого
окружения. Linux-пакет содержит Godot-проект и установщик для Arch; это
исходная поставка, Godot скачивается при установке. В каждый архив входят только
команды его ОС. Python-код, сцены и ресурсы развиваются совместно.

Linux-архив можно упаковать на любой ОС с Python 3.11+: упаковщик сохраняет
Unix-права и LF в `.sh`. В Windows с готовым окружением:
`.venv\Scripts\python.exe scripts\package_arch.py`.
Для Windows-сборки нужны Windows и подготовленные `scripts/build_windows.ps1` инструменты.
Обе платформы устанавливают зависимости по общему `uv.lock` с маркерами ОС.
Используйте отдельные распакованные папки для каждой ОС: `.venv` и `.tools`
содержат платформенные исполняемые файлы.

[Разбор LINDEMANN/Control и план изменения анатомии монстра](docs/MONSTER_DIRECTION_RU.md).

**Основной режим — нейронная сущность без общей сетки и скелета.** SD 1.5 с DPM++ 2M Karras, 512×512,
генерирует меняющийся человеческий образ, TripoSR предсказывает плотность и цвет
во всём объёме. Godot рисует поле 192³ трассировкой лучей и сохраняет детали лица
из сгенерированного изображения. Очередь держит до трёх будущих состояний,
следующее загружается заранее. Непрерывный переход меняет
сам объём, включая отверстия и отдельные компоненты. Форма одна для всех ракурсов.
Готовые головы и руки в этом режиме не добавляются. [Устройство и ограничения](docs/NEURAL_ENTITY_RU.md).

Шаг шума по умолчанию 0.5, сила перерисовки 0.82. Почти одинаковые изображения
не публикуются в очередь: генератор увеличивает шаг. Плавность задаётся
шестисекундным переходом между объёмами, поэтому заметная мутация не требует
резкой смены кадра.

`Start SpookyNeuro.cmd` запускает живую генерацию. `Neural Entity Demo.cmd`,
`Offline Preview.cmd` и старое имя `Mutation Demo.cmd` воспроизводят 12 сохранённых
нейронных объёмов без запуска моделей. В Linux: `bash scripts/run_3d.sh --offline`.
WASD / ПКМ — движение и обзор, O — обход, M — заморозка, G — пауза генерации,
F — эффекты, Tab — панель, N — следующий завершённый переход в демо.

Предыдущий опыт с мешами, ригом и дополнительными конечностями сохранён за
`--legacy-mesh` и в `room_3d.tscn`. [Его описание](docs/MUTATIONS_IMPLEMENTED_RU.md),
[экспорт моделей и Unity](THREE_D.md). Он больше не является основным режимом.

Установка из ZIP на другой Arch Linux: **[INSTALL_ARCH_RU.txt](INSTALL_ARCH_RU.txt)**.
Из GitHub можно установить тот же проект (требования к Arch и NVIDIA — в инструкции):

```bash
git clone https://github.com/Menoitami/Strashilka.git
cd Strashilka
bash scripts/setup_3d.sh
bash scripts/run_3d.sh
```

Инструкция входит в архив. После распаковки в `~/Games/SpookyNeuro` и установки:

```bash
bash "$HOME/Games/SpookyNeuro/scripts/run_3d.sh"
```

`scripts/run.sh` без аргументов и `scripts/run_3d.sh` сначала загружают модели и получают первый настоящий нейронный объём. Только затем открывается комната: с первого видимого кадра монстр уже нейросетевой, работающий процесс продолжает генерацию без перезагрузки. Стадии подготовки и путь к журналу видны в терминале. Закрытие игры останавливает процесс; Ctrl+C отменяет загрузку. Прямой Play в редакторе Godot воспроизводит сохранённые нейронные объёмы.

Далее — сведения о прежних режимах, их настройках и исторических замерах.
В режиме `--legacy-mesh`: WASD — движение, ПКМ — осмотр, P — приближение монстра,
M — заморозка, G — генерация, V — испарение, F — фонарь, Tab — панель.
Пресет «Реалистичная плоть» сохраняет общую сетку, UV 1024×1024 и риг.
Просмотрщик исходного GLB: `scripts/run_3d.sh --viewer`.

Новая основа — реконструированный по фотореалистичному референсу гуманоид с более естественными пропорциями. Материал кожи получил микрофактуру, неоднородную влажность и ограничение накопительного цветового дрейфа. Комната использует бетон, трубы, направленный свет и фонарь. В панели отдельно доступны разрешение лица 384/512, шаги текстуры 4/6/8, стабильность цвета, свет, зерно, влажность и детализация кожи. «Сохранить»/«Загрузить» охватывают эти параметры, seed, режим материала и переключатели. Последний прогон: **54,5 FPS**, 11 принятых состояний за 65 секунд; это прототип, не достигнутый кинематографический фотореализм.

Лицо теперь обновляется отдельно: по умолчанию **3 лица на одну форму тела**, собственный переход **1,2 с**. Параметры «Лиц на одну форму» (1–6) и «Переход лица, сек» сохраняются вместе с остальными настройками. Дополнительные проходы меняют только лицевую текстуру и normal map, сохраняя память предыдущего лица; тело продолжает своё плавное превращение. Проверено на RTX 2080: **18 обновлений лица / 6 форм за 50 секунд**, отдельный проход лица **1,48–1,61 с**, сцена **56,1 FPS**. Вычисления используют одну GPU по очереди, поэтому при генерации новой геометрии лица ждут.

Ниже описан исходный 2D-режим: Godot рисует комнату и коллизии, SD 1.5 + LCM-LoRA меняет только изображение существа. Оно проецируется на ориентированный к камере квадрат; optical flow сглаживает переходы. Для него существует команда `scripts/run.sh --2d`.

## Запуск

На этом компьютере окружение и Godot находятся в `.venv` и `.tools`. Из корня проекта:

```bash
scripts/run.sh --2d
```

Первый запуск скачивает SD 1.5 и LCM-LoRA в пользовательский кеш Hugging Face. Окно игры открывается сразу, подключение к модели происходит после её загрузки. Если локальная художественная LoRA уже обучена, `run.sh` подключает её автоматически. Подробности запуска — `artifacts/renderer.log`.

```bash
scripts/run.sh --lora artifacts/horror-lora/lora
scripts/run.sh --mock
scripts/run.sh --config configs/fast.json
```

`--mock` — диагностическая деформация изображения, **не нейросеть**. Надпись MOCK показывается в сцене. На новом компьютере сначала выполнить `scripts/setup.sh`: он устанавливает локальные uv, Python 3.12, зависимости из `uv.lock` и Godot 4.7.2. Нужны Linux x86_64, интернет и NVIDIA с рабочим драйвером CUDA; системные пакеты скрипт не меняет.

Управление: **WASD** — движение, **правая кнопка мыши** — осмотр, **Shift** — бег, **Esc** — отпустить курсор. **M** переключает сгенерированный силуэт / маску манекена, **I** — optical flow / смешивание, **P** — включить/остановить приближение монстра с походкой, **F12** сохраняет сцену и исходное изображение монстра в `user://` Godot. Абсолютный путь выводится движком. Справа регулируются сила преобразования, период шума, вес художественной LoRA и множитель длительности перехода.

Область нейросети задаётся в `configs/default.json`. Начальные настройки: сгенерированный силуэт, 256×256, 4 запрошенных шага, strength 0.65 — **2 фактических шага img2img**. На RTX 2080 отдельный стенд с обученной LoRA и свободной маской CUDA дал 3,11 обновления/с; десятиминутный сценарий в игре — 59,99 FPS сцены. Подробные условия и ограничения замеров — в `RESULTS.md`. LoRA weight действует, когда загружена художественная LoRA. `configs/fast.json` задаёт один фактический шаг, сокращая вычисления и детализацию; его скорость отдельно не подтверждена.

## Бенчмарк и проверки

```bash
.venv/bin/spooky benchmark --matrix --frames 12 --output artifacts/baseline
.venv/bin/spooky benchmark --mask free --output artifacts/free-mask
.venv/bin/spooky benchmark --interpolation blend --output artifacts/blend
.venv/bin/spooky benchmark --lora artifacts/horror-lora/lora --output artifacts/trained
.venv/bin/pytest -q
.venv/bin/ruff check src tests
.tools/godot --headless --path godot --script res://tests/rig_check.gd
scripts/soak.sh
```

Бенчмарк прогревает модель, сохраняет ключевые PNG, GIF-последовательность, CSV по кадрам и `report.json`. При наличии ffmpeg рядом с GIF экспортируется MP4. `peak_vram_mib` учитывает память PyTorch; `device_used_mib` — всю занятую память GPU, включая ONNX Runtime, Godot и рабочий стол. Время записи PNG на диск и CPU-экспорт анимации не входит в `median_service_ms`: это сумма рендера, маски, optical flow и PNG-кодирования. Передача по TCP и задержка буферизации измеряются интеграционным запуском отдельно.

`soak.sh` запускает сцену на 10 минут с повторяемым движением камеры, сменой маски и интерполяции. Результат — `artifacts/soak.json`, снимок и журналы. Для проверки обучения отдельно выполнить тот же тест с `--lora artifacts/horror-lora/lora`. `scripts/record.sh --lora artifacts/horror-lora/lora` записывает короткое видео подхода, а `.venv/bin/python scripts/replay.py` сравнивает optical flow и смешивание на одинаковых сохранённых кадрах.

## Данные и обучение

```bash
.venv/bin/spooky collect --per-class 250 --delay 2
.venv/bin/spooky prepare
.venv/bin/spooky train --steps 1000
```

Коллектор сохраняет изображения людей, животных и монстров из Wikimedia Commons, а также автора, страницу источника и лицензию в `data/commons/manifest.jsonl`. Фильтр принимает public domain, CC0, CC BY и CC BY-SA; условия конкретных файлов остаются в манифесте. Коллектор возобновляемый, не обходит ограничения сервиса и делает паузу при ответе 429. Наличие подходящих изображений зависит от результатов поиска.

Контактные листы `data/commons/contact_*.jpg` помогают проверить набор. Неподходящие идентификаторы можно записать по одному в `data/commons/exclude.txt`, затем повторить `prepare`. Подготовка удаляет точные и близкие дубликаты до разделения train/validation, сохраняет пропорции и дополняет изображение до квадрата. Набор из открытых источников содержит фотографии, исторические изображения и скульптуры; художественную пригодность проверяем по фактическим результатам, а не по training loss.

Обучение: UNet LoRA rank 8, FP16, gradient checkpointing, batch 1, gradient accumulation 1, AdamW 1e-4, выборка с равной вероятностью трёх классов, VAE и текстовый энкодер заморожены. Латенты и текстовые представления кешируются в RAM до загрузки UNet. Обучение и игра запускаются по очереди, чтобы не конкурировать за 8 ГБ VRAM. CLI блокирует одновременный запуск нескольких нейросетевых задач этого проекта. При OOM снизить `--size 384`; это изменение нужно учитывать при сравнении качества.

Каждые 250 шагов и в конце сохраняются полное состояние, LoRA и validation loss. Проверочные примеры включают все три класса; их шум фиксирован между замерами. Метрики пишутся также в `metrics.jsonl`. Последняя LoRA — `artifacts/horror-lora/lora`. Продолжение:

```bash
.venv/bin/spooky train --steps 1000 --resume artifacts/horror-lora/checkpoint-250
```

Возобновлять с тем же набором, rank, размером и gradient accumulation. Ctrl+C сохраняет завершённый шаг. TensorBoard: `.venv/bin/tensorboard --logdir artifacts/horror-lora/logs`.

## Как работает интеграция

Godot снимает только отдельный прозрачный viewport с моделью существа. Python выполняет img2img с детерминированным VAE и плавным смешением двух полей шума; фон игровой сцены в модель не передаётся. Результат накладывается с проверкой глубины, поэтому колонна перекрывает существо.

- **Фиксированная маска:** контур берётся из 3D-модели. Меняются цвет и детали внутри контура.
- **Свободная маска:** U2NetP (автоматически на GPU, CPU через `--mask-device cpu`) отделяет фигуру от сгенерированного фона. Первый запуск скачивает отдельные веса; маска необычной анатомии может быть неточной. Коллизии остаются у исходного объёма.
- **Интерполяция:** CPU DIS оценивает поток в обе стороны и проверяет согласованность. Godot деформирует и смешивает изображения и маски; ненадёжные области используют обычное смешивание. Это приближённая интерполяция, она не восстанавливает невидимые поверхности.

Нейросеть всегда получает квадрат с изолированным монстром. При наложении вырезается либо получившийся силуэт (по умолчанию), либо маска манекена. Фон комнаты не проходит через диффузию: эксперимент с квадратным участком комнаты был убран после визуальной проверки. Манекен состоит из соединённых объёмов с плечами, суставами, кистями, ступнями, рёбрами и чертами лица. Риг из 14 суставов задаёт несимметричную походку: наклон корпуса, короткий шаг левой ноги, качание рук и редкие повороты головы. Монстр медленно приближается и останавливается рядом с игроком; поза рига поступает в img2img.

Буферизация перехода добавляет задержку примерно на один интервал генерации. Новая пара не прерывает незавершённый переход; очередь отображения ограничена двумя результатами. При пропуске промежуточного кадра несовместимый optical flow отключается. Смена режима или большой ракурс сбрасывают последовательность. При отключении Python остаётся последнее изображение, клиент переподключается.

TCP слушает только `127.0.0.1:7861`. Формат: u32 big-endian длина JSON, JSON с длинами бинарных блоков, затем блоки в порядке ключей `blobs`. Вход — RGBA PNG и метаданные; выход — RGBA PNG, метрики и два массива flow H×W×4 float32 little-endian (dx, dy, confidence, 0). Протокол описан в `src/spookyneuro/protocol.py`.

## Ограничения эксперимента

Один монстр, приблизительные коллизии и глубина плоского изображения. Приближение монстра прямолинейное, обход препятствий не реализован. Нейросеть может терять связь с позой; ControlNet и полноценная генерация геометрии не включены. Низкое разрешение намеренное, но само по себе не гарантирует пугающий эффект. Фактические результаты и статус обучения см. в `RESULTS.md`.
